# CFOP 阶段与时间分析修改记录

已实现 C→F→O→P 的顺序状态判定。Cross 完成时实际在位的 F2L 组数决定 Cross／xcross／xxcross／xxxcross／xxxxcross；这些组的用时包含在 C，F 明细以 0 秒和“已包含在 Cross”表示。删除原先超过 20 步时强制改名的限制。

F2L 结束必须在同一状态下满足 Cross 和四组 F2L 全部正确。每组插入仍按先后记录，后续动作中的临时位移不新增阶段；最后一组的结束边界采用实际完整 F2L 时刻，防止累计“曾经完成”的槽位提前进入 O。O、P 根据状态独立计时，公式匹配失败不抹除时间。保留合法跳步、零用时和末尾 AUF 用时。

底面优先使用成绩详情中明确选择的面；自动模式使用最早形成完整 F2L 的面；同一个状态出现多个候选时不强选，允许手动指定。界面显示选择结果和选择控件，不说明内部规则。底面属于分析输入，修改后旧任务的结果不能覆盖新选择，JSON 和 CSV 保留该选择。

删除底面加权评分、评分惩罚、所有置信度字段及相关显示。OP 改用精确匹配数量校验，保留公式重放验证。成绩分析和复制统计以时间、时间占比、平均值、标准差及时间差为指标，移除固定阈值的稳定性、清洁度和蓝牙效率评价。

动作时间缺失时在前后已知时间间线性插值；状态包显示关键阶段跨越但中间动作缺失时，在该状态区间内按阶段顺序插值。完整记录的实测时间保持原值，重复确认包不延后边界，最后阶段以停表用时结束。插值信息仅作为派生数据保存，不改写原始动作。

兼容性修复：精简启动数据只要省略了原始动作便标记为待补载，打开详情立即补载并刷新复原面板；空时间及包计数字段保持 null，避免重复归一化把 null 变为 0、改变分析输入身份并导致界面停留在“分析中”。

CFOP 分析版本升级为 8，OP 升级为 5。重启后，具备原始证据的旧记录通过现有后台分析队列重新计算；桌面应用 runtime 与浏览器构建已同步。
