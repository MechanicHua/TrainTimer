# 性能优化实施与验证 · 2026-09-29

本轮已经修改运行代码、生成浏览器 bundle，并同步 `TrainTimer.app/Contents/Resources/runtime`。基于 9 月 28 日审查时的工作区继续实施，保留此前已有改动。全部测试使用临时或合成成绩，没有写入个人成绩文件。

## 已实施

- **3D 调度**：姿态更新与转层使用同一条 requestAnimationFrame 调度链，取消渲染前导致隔帧的时间门限。静止后停止绘制。保留当前 Three.js 模型、材质和实例绘制。
- **快速输入**：把通知收到的时间传递到转层动画；按输入间隔和积压时间缩短视觉动画。队列最多积压 3 个转层，溢出时按顺序提交目标状态，再绘制最新动作。原始转动记录、计时与状态推导不丢步。
- **公式切换**：旧、新文字并行进行 180/200 ms 的位移与透明度动画，取消 680 ms 入场等待和模糊纹理预计算。保留 reduced-motion 和中途切换清理。
- **打乱修正**：深度 4 的短搜索放到独立浏览器 Worker；一个执行任务和一个最新待执行任务。过期请求不会回写当前公式；Worker 不可用时走服务器。复杂状态继续使用已有 min2phase，后台队列串行、可跳过无人等待的任务，并限制启动等待和排队数量。已经开始的有界搜索完成后才执行下一项。
- **复原分析**：停表先显示结果、保存原始数据；CFOP/OP 使用独立 Node Worker，共享一次 CFOP 分析上下文。保存算法版本、原始数据修订号和分析摘要；详情、比较和 OP 统计读取派生结果。原始转动或补发状态变化会失效旧分析；编辑备注或罚时不触发重算。历史分析逐条处理，计时期间暂停派发。
- **结果一致性**：后台结果以完整原始证据校验，不能覆盖后续编辑或被删除的记录。导出需要分析字段时等待结果；复盘缓存含状态修正的逐步快照，并给每次播放分配编号，避免旧回调污染新播放。
- **历史列表与统计**：紧凑列表和完整列表只挂载视口附近的行；筛选、排序、全选和导出仍使用完整数据。滚动平均使用滑动和、DNF 计数与单调队列计算极值，最佳区间也使用线性扫描。数值未变化时复用指标，同时更新成绩对象，避免备注或分析数据变旧。
- **保存与后台进程**：历史写入按路径串行，以临时文件和原子重命名完成；停表保存只返回新成绩，避免回传整份历史。TNoodle 使用同一版本库的常驻适配器，保留原来的生成/绘图调用；最多 8 个未完成请求，空闲 60 秒释放。自定义 TNoodle 命令优先级不变。预览缓存限制为 32 项。
- **构建**：esbuild 将浏览器模块统一打包，消除带查询参数与不带参数的重复模块实例；Three.js 仍按需加载。源码哈希清单和运行时镜像测试防止交付旧 bundle。

## 实测

环境为 M1 Pro、Node 23.11、Chromium 153 headless，同机桌面测试。以下不是手机或真实蓝牙延迟数据。

| 项目 | 优化前/参考实现 | 优化后 |
| --- | --- | --- |
| 180 次持续姿态输入，约 10 ms 间隔 | 29.61 FPS | 59.65 FPS |
| 稳定后的静止绘制 | 0 | 0 |
| 新公式入场等待 / 动画总结束时间 | 680 / 1320 ms | 0 / 200 ms |
| 万条成绩的 mo3、ao5/12/50/100，CPU 中位数 | 75.85 ms（同输入原算法） | 2.31 ms |
| 万条历史实际 DOM | 原实现挂载全部 | 首屏 21 行，滚动约 29 行 |
| TNoodle SVG 绘制中位数 | 约 169 ms | 1.93 ms |
| TNoodle 生成中位数 | 约 524 ms | 209 ms（本次 3 个样本含一次冷启动） |

TNoodle 首次启动本次为约 768 ms，比此前单次 CLI 的约 524 ms 更慢，原因包括 Java 源码适配器编译；收益在后续复用和绘图。常驻进程会暂时保留内存，因此没有宣称全应用总内存或功耗下降。当前仅预取下一条打乱，缓存耗尽后的首次请求仍需等待生成。

60/120 步合成复原的共享上下文分析中位数约 20.3/38.5 ms，CPU 算法时间仍存在；本轮的主要改善是将它移出浏览器交互线程，并复用已完成结果，不能把它说成计算本身已经接近零成本。

## 验证结果

- `npm test`：371 项全部通过，包含原有协议、CFOP、导入导出和统计测试。
- 新增随机差分测试核对一万条数据的平均值、DNF、+2 和并列情况；后台分析与同步参考结果对照；Worker 取消、取最新任务和失败后重建；并发保存、过期分析拒绝；带物理步骤修正的半转回放。

- 2–7 阶、Clock、Skewb、Square-1 均用常驻 TNoodle 完成打乱与 SVG 绘图。
- macOS 包内运行时与源码同步；Windows 的源码打包路径保持兼容，本机未编译或运行 Windows 原生安装包。

## 复跑与边界

```sh
npm run build:web
npm test
mkdir -p output/performance-audit
node scripts/performance-audit.mjs > output/performance-audit/node-after.json
```

仍需实际手机、真实 GAN 设备与长时温升/功耗测试，不能凭桌面模拟保证每台手机 60 FPS，或声称已经达到 Cube Station 的实机表现。

没有迁移 SQLite、没有更换引擎或引入 WASM。历史存储仍会读写完整 JSON，浏览器仍保留完整成绩集合；因此五万条以上且含大量蓝牙原始日志的数据集仍需专项存储与内存评测。本轮使用线性批量统计，尚未引入所有编辑场景的增量索引。OP 公式库仍随主 bundle 加载。它们属于方案中的后续扩展，未计为本轮已经达成的收益。
